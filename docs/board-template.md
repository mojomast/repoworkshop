# Bundled Planning-Board Template

RepoWorkshop 0.3.0 includes a dependency-free board at [`skills/repository-planning-workshop/templates/board/`](../skills/repository-planning-workshop/templates/board/). Copy it into an approved project-local workshop boundary; installed files remain immutable.

The example and implementation use the same [canonical data contract](../skills/repository-planning-workshop/references/canonical-data-contract.md): typed IDs, validated evidence and research baseline, `sha256:` baseline/manifest/state/snapshot digests, Unicode-scalar canonical JSON, exact answer order, and strict unknown/duplicate-key rejection. The manifest self-digest omits only `manifestDigest`. State self-digest omits only `stateDigest`. The browser receives the validated canonical manifest projection and derives all records from it.

An absent state produces a no-write synthesized revision `0`. This value exists only at the GET/API boundary so a first save can use `expectedRevision: 0`; persisted revisions are always at least `1`. Server-owned revision, timestamp, readiness, and `stateDigest` are recomputed on every save. A ready persisted state can produce the exact approved-selection snapshot consumed by Retrieve/Plan.

One isomorphic pure evaluator is loaded directly by both Node and the browser. Readiness fails with focusable record IDs for unfinished dispositions, missing reasons, direct or transitive Build dependencies that are disabled/non-Build, required and dependency decisions that are unanswered, and every unresolved/contradictory blocker predicate. Selecting Custom with blank text is a valid saved draft but remains unanswered; optional unanswered choices do not block. Multiline custom answers render as textareas; single-line/nonblank modes render as text inputs with the same effective limits and line rules as state validation.

Writable persistence opens the approved owner-only state directory once with `O_DIRECTORY|O_NOFOLLOW`, verifies a descriptor path resolves to that inode, and anchors every read, temporary, backup, rename, cleanup, and directory fsync through that retained descriptor. Linux uses `/proc/self/fd`. It rechecks the original pathname without following it after publication and reports replacement while leaving state only in the opened original directory. Recovery returns a prior validated backup rather than corrupted final state. The state directory must be pre-created; no race-prone pathname creation is attempted. Platforms without a verified descriptor path fail closed for writes and can use manual loopback read-only mode.

The HTTP server has strict Host/Origin/media/framing checks, JSON 413 overflow responses, four concurrent mutation slots, body and connection caps, and explicit header/request/keep-alive timeouts. This bounds one local process; it does not provide DoS resistance, authentication, authorization, TLS, or multi-user merging. Prefer loopback.

Exports remain `.txt`, begin `REVIEW ONLY - NON-AUTHORITATIVE`, and render all user-controlled multiline content as escaped indented plain text. Deterministic tests cover pure transitions/helpers and static controller wiring only. When installed Chromium is available, the optional test loads the actual served capability-path board, checks its rendered controls/security route, and verifies reported 320px overflow; it skips honestly otherwise.

See the template [README](../skills/repository-planning-workshop/templates/board/README.md) for copy/launch commands and the [security model](security-model.md) for trust boundaries.
